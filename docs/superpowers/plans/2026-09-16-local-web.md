# Standalone Local Web Implementation Plan (Historical Execution Record)

[中文版本](2026-09-16-local-web_zh.md)

> **Historical record (2026-09-16):** Standalone local Web is complete; the original `feat/local-web` branch was later merged into `main`. Current entry points, lifecycle, and data boundaries are defined by the [architecture](../../architecture.md), the [local Web guide](../../../apps/web/README.md), and the [landed specification](../specs/2026-09-16-local-web.md). This file preserves scope and decision rationale and is not an unfinished task list.

## Objective and constraints

Use one Host, protocol, transport, and UI implementation for Desktop and standalone local Web. SSH is always initiated by the user’s computer; Web binds only to loopback and provides no public service, accounts, or user isolation. Web credentials are used only in the current page; Desktop retains operating-system encryption. The implementation uses npm workspaces, TypeScript, Cordis, ssh2, xterm, Electron, and Node HTTP/WebSocket.

## Implementation scope

1. Extract `packages/{protocol,host,transport,ui}`, establish the root workspace and single lockfile, and update Desktop imports, resource paths, check scripts, and test paths.
2. Inject `CredentialProvider` into Host; prohibit secrets from being written on the session-only path while preserving Desktop persistence compatibility; add client disposal and connection-close protection.
3. Use runtime capabilities to distinguish native and browser private-key selection, disable Web credential memory, and cover in-memory behavior.
4. Add the `apps/web` Node server/CLI, restrict binding to loopback, print the startup URL, and implement complete shutdown; verify real SSH/SFTP, save, disconnect, and exit behavior.
5. Add capability declarations and connection cleanup to transport; assemble safeStorage, shared resources, and the existing readiness state in Desktop.
6. Update architecture, layout, and startup documentation; run build, type, boundary, Node, Electron, and browser checks and complete an independent review.

## Completed

- Four shared packages and two entry points are present. Desktop runs through an independent Node Host child process; Web assembles Host in its own Node process.
- Web stores host metadata and trusted fingerprints only, never passwords, passphrases, private-key content, filenames, or paths; it rejects legacy credential files instead of migrating or overwriting them.
- HTTP/WS binds only to `127.0.0.1` and uses a startup token, session cookie, and Origin/Host checks; closing a page releases its SSH sessions.
- Fixed cross-port cookie collisions, a smoke test that did not rebuild shared packages, exit hangs when SSH peers omitted FIN, token remnants in the address bar, and browser private-key authentication.
- Current publishing and verification entry points are root `npm run verify`, `npm run verify:electron`, and the [release guide](../../desktop-release.md).

## Immutable boundaries

Standalone local Web does not provide public deployment, remote control, user accounts, multi-tenancy, or a credential service. Do not let it share an active data directory with Desktop or treat a browser filename as a local absolute path. Desktop persistence must continue through the entry-point-injected operating-system encryption provider.

## Historical verification scope

Windows verification covered the root build, type/boundary checks, Node regressions, Desktop boot/IPC/attached Web, standalone Node Web in a browser, real SSH/SFTP, credential policy, and shutdown cleanup. A hidden-window environment could not provide screenshots; other operating systems and installers were outside that phase’s local acceptance. Current cross-platform build and signing boundaries are in the [release guide](../../desktop-release.md).
