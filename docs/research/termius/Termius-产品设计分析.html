Termius：把 SSH 客户端做成「服务器资产与凭据管理系统」

本文基于对本机正在运行的 Termius 的**直接操作**（逐屏点击、逐屏截图）与对其 Electron 安装包的**解包读取**写成。所有结论标注了证据强度：【实测】= 在界面上看到或在二进制里读到；【推断】= 由间接证据得出的判断。

01一句话结论

Termius 的界面本质是一个双态应用：管理态是「列表 + 右侧检查器」的主从结构，管的是主机、凭据、转发规则、代码片段这些资产；会话态则整个窗口让位给终端，导航栏收起。它真正卖的不是「一个能连 SSH 的终端」，而是一套团队共享的服务器资产库——凭据不内联在主机里、而是引用钥匙串条目，Vault 分为 Personal / Team 两级作用域，配合同步、共享、角色权限。这是它和 PuTTY（配置文件散在注册表）、iTerm2（本地偏好）、Tabby（本机配置）的根本分界。

02界面结构：三层，各管一件事

2.1 一级导航只有六项【实测】

左侧导航栏是一列「图标 + 名称」的条目，六项：Hosts（主机）、Keychain（钥匙串）、Port Forwarding（端口转发）、Snippets（代码片段）、Known Hosts（已知主机指纹）、Logs（日志）。

这六项不是随便凑的，它对应了 SSH 客户端真正需要长期保存的六类东西：连哪儿、用什么身份连、连上之后把什么端口打通、连上之后要敲什么、怎么确认对面没被换掉、连过之后留下什么。把「Known Hosts」提为一等公民而不是埋在设置里，是一个安全取向的选择——TOFU 指纹在多数客户端里是弹一次就忘的。

2.2 标题栏是「工作区」而非装饰【实测】

窗口是自绘标题栏（frameless），里面塞了三组东西：

  • 作用域切换：Vault 药丸（体+箭头分开点，箭头才展开列表）+ 同步状态图标；
  • 标签页：+ 新建；SFTP 也是一个标签，和终端会话平级；
  • 窗口按钮：最小化/最大化/关闭由应用自己画（右侧），另有 Update 按钮、通知铃铛、帮助。

把「标签页」放在标题栏而不是内容区顶部，说明它的定位是工作区管理：一个标签就是一个工作上下文，可以是终端、可以是 SFTP、可以是串口。实测我误触菜单打开过一次「本地终端」，窗口标题随即从 Termius - Hosts 变成 Termius - Local Terminal——标题跟随当前标签，且此时左侧六项导航整个消失，内容区只剩标签栏 + 终端。

会话态让位：一个明确的心智切分

进入会话后导航栏收起，是这份界面里我最欣赏的一个决定。它承认了「管理主机」和「在终端里干活」是两件互斥的事：前者需要导航和列表，后者需要每一像素都留给字符。很多客户端（包括不少 Web 终端）做不到这一点，把一个常驻侧栏一直挂在终端旁边。

2.3 工具行随区块变形【实测】

内容区顶部那行不是固定工具栏，而是按当前区块重建的：

区块主操作次操作搜索

03核心对象模型：主机、凭据、金库、工作区

界面背后有几个对象，理解了它们就理解了整个产品的骨架。【实测】靠「选中主机 → 右侧检查器 + Show more + 段落级 ⋯」逐层读出。

3.1 Host 是一个「机器」，可以挂多种接入方式

检查器顺序为：Address（地址，左侧是这台机器的图标）→ General（Label / Parent Group / Tags / Backspace）→ Share this host → SSH on｜端口 22 → Credentials → Show more → + Add Telnet → 底部常驻 Connect。

最有信息量的是最后那个 + Add Telnet：它说明「主机」不是「一条 SSH 连接」，而是「一台机器」，下面挂着一张连接方式的清单。SSH 和 Telnet 是同级的段落，可以叠加。这比「一个配置 = 一次连接」的模型更贴近现实（同一台交换机你可能既想 SSH 又想走串口）。

3.2 凭据是引用，不是内联【实测】

凭据段落里显示的三行是：用户名、Password（占位符，右侧有眼睛图标可显形）、以及一个钥匙串里的条目名（形如 <keyname>.pem）——最后那个是引用，不是密钥内容。再往下是 + SSH ID, Certificate, FIDO2，即给同一台机器追加第二条认证路径。

这一条和你们项目的判断完全一致

你在 ssh-cordis-client 里做的就是这件事：主机元数据（hosts.json）绝不存放任何密文，只存 privateKeyPath 这个路径，真正的密文单独放在 secrets.json，定位是「可以放心备份/同步」。Termius 走的是同一个结构，只是把「路径」换成了「钥匙串条目名」，并且把钥匙串本身做成了一个可视化的管理界面（Keychain 区块，列出每个密钥的名字与类型）。这说明「主机元数据可同步、秘密不可同步」是这个领域里正确的切分，不是取舍。

3.3 凭据的形态比想象中多【实测 + 实测】

Keychain 区块的工具栏直接列出四种：普通密钥、证书、Windows Hello、FIDO2。而包依赖里还能读到更硬的证据：

依赖说明

@termius/libfido2实测FIDO2 硬件密钥的原生实现
@termius/keytar实测密钥交给操作系统钥匙串保管（Windows 凭据管理器 / macOS Keychain）

把 registry-js 和图标集里的 putty / secureCrt / mobaXterm 放在一起看，可以推断：推断它提供从 PuTTY（注册表）、SecureCRT、MobaXterm 一键导入既有主机的能力。这是一个非常聪明的获客设计——迁移成本是换 SSH 客户端的最大阻力，谁先把迁移做成一键，谁就先把人捞过来。

3.4 Vault 决定「谁能看到」

Vault 是资产与凭据的容器，作用域只有两级：Personal 与 Team。【实测】图标集里有 vault / vault.password / vaultWarning / all_vaults / vaults.many / vaults.single / group_shared / no-keys-sharing-icon / role-gradient / owner / guest 这一整族，说明【推断】Vault 之上还有按条目粒度的共享与角色（owner/guest），并且能单独控制「哪些密钥不参与共享」。检查器里那个蓝色的 Share this host 就是这个体系的入口。

3.5 其余两个对象的定位很讲究

  • Snippets：可复用的命令片段。界面上显示的是片段正文（例如一条 cd 命令）而不是给它起的名字——对一个「敲命令的人」来说，命令本身辨识度更高。
  • Shell History：和 Snippets 并排的独立按钮。推断这把「我自己敲过的命令」也当成一种可检索资产，和「我特意存的片段」并列存放。

另有 Known Hosts（TOFU 指纹独立成栏）和 Logs（会话日志）。你项目里的 known_hosts.json 正对应前者。

05做得好的地方（可迁移）

1. 检查器，而不是弹窗或新页面

选中主机后，右侧滑出 Host Details，列表还在，只是从 3 列自适应重排成 2 列。这比「点开进入详情页（丢失列表上下文）」「弹模态框（丢失视野）」都好。而且检查器底部常驻 Connect 按钮——无论面板滚到哪，主操作永远在同一个位置。

迁移建议：编辑表单做成并排检查器，让列表保持可见；主操作按钮固定在面板底部而不是跟随内容滚动。

2. 渐进披露（Progressive disclosure）贯彻得很彻底

一个主机面板里就能看到三层：默认可见（地址、标签、端口、凭据）→ Show more（展开更多段落）→ 段落级 ⋯（SSH 段落自己还有更多选项）。新手看到的是 6 个字段，老手能找到 60 个。你项目里的主机表单只有一个平面，这是最容易改、收益最直接的一处。

3. 把「危险操作」做成独立区块，而不是埋在字段里

Share this host 单独一行、用蓝色强调、居中、带人形图标——它既有视觉优先级，又和上下文的表单字段明显分离。共享是权限动作，不是属性编辑，UI 上分开了。

4. 凭据形态丰富，且「同一台机器多条认证路径」是一等公民

密码 / 密钥 / 证书 / Windows Hello / FIDO2 / SSH ID 并列可选，还能给一台机器叠加多条。推断这对「同一台机器不同环境用不同身份」的真实场景（生产用硬件密钥、测试用密码）是直接支持的。

5. 空状态、次级按钮、搜索框都按区块裁过

  • 空状态写「用途」不写「机制」；
  • 次级按钮直接暴露该区块的变体（Keychain 的 Certificate / Windows Hello / FIDO2）；
  • 只有高频找东西的区块（Hosts）才给常驻搜索条，其余退化为图标。

06我认为不够好的地方

1. 汉堡菜单是系统原生菜单，和暗色界面严重割裂

这是我在界面上最不适的一处。实测点击左上角汉堡后弹出的是一个 Windows 经典样式的浅色原生菜单：Vaults Ctrl+1、SFTP Ctrl+2、Settings Ctrl+逗号，然后 New Local Terminal、New Serial Connection、Edit ▸、View ▸、Window ▸、Help ▸、Exit。

问题有三层：(a) 视觉上是两套设计语言的拼接（macOS 上原生菜单是加分项，Windows 上是减分项，同一个决定在两个平台收益相反）；(b) 它把 Ctrl+1/Ctrl+2 这种「标签切换」写进系统菜单，而快捷键设置页里也有一套标签相关快捷键——同一个能力两处定义；(c) 命令行风格的本应用里，一个 2005 年观感的菜单是明显的外来物。推断这可能是 Electron Menu.buildFromTemplate 的默认路径，属于「技术债外溢到 UI」。

2. Settings 是一个独立窗口，并且长出了第二套导航

Settings 开在单独窗口（1655×1025），左侧另有一整套导航：Account、SSH ID、Invite People、Terminal、SFTP、Logs、Shortcuts、Theme，再往下是一串外链（Documentation / Request a Feature / Report a Bug / Termius Beta Program / Changelog）。结果是应用里存在两套并列的导航语义：主窗口的六项 vs 设置窗口的十三项。尤其 Logs 在两边都出现（一处是会话日志、一处像是应用日志），用户很难预判点哪个才对。把「请求功能 / 报 Bug / Beta 计划」这类社区外链塞进设置导航，也把设置页变成了半个关于页。

3. 命令面板不是全局的——它把最该被命令化的动作留在了菜单里

实测在主机管理态按 Ctrl+K 没有任何反应（同一时刻 Ctrl+, 能正常打开设置，所以不是键盘没送达）。也就是说命令面板只活在会话里。可「打开主机管理」「打开设置」「跳到某台主机」恰恰是最适合命令面板的动作——而它们现在都在那个原生菜单和搜索框里。看到一个键位为命令面板预留（还专门写了迁移标记），却不能全局调用，是挺可惜的落差。

4. 信息密度偏低，宽屏浪费明显

我这台是 2560 宽的屏。三列卡片布局下，每张卡片约 515px 宽，却只装了「一个图标 + 主机名 + 两个标签」。第二行那个标签位实际是标签（tags），用来显示 ssh、ubuntu、root 这类信息——其中 ssh 对每台机器都一样，属于零信息量的重复。真正有价值的状态（最近连接时间、是否在线、上次连接的延迟）全都没有。一个管几十台机器的人，靠的是搜索而不是扫视。

5. 选择态过重，且「选中」与「连接」的视觉区分不够

实测被选中的卡片是整块蓝色填充（实测像素 rgb(35,102,166)），在暗色界面里非常炸眼。而它表达的只是「选中」，不是「已连接」也不是「正在连接」。在一个以暗色为基调的界面里，把最大面积的强调色给一个临时状态，会持续抢走注意力。

如果只从 Termius 拿三样东西

  1. 远端 shell 集成（注入 bashrc/zshrc/fish，回报 cwd 与退出码）。它能一次点亮「新标签继承目录」「命令历史」「终端内搜索」三件事，而且和你的插件结构天然契合——完全可以做成一个新的 Cordis 插件。
  2. 命令面板（先做成全局的）。把「打开设置 / 新建主机 / 跳到某主机 / 打开某个会话」都收进一个模糊搜索里。你已经有 METHODS 常量表，动作表几乎可以照着它生成。
  3. 渐进披露的编辑表单（默认 6 个字段 + Show more + 段落级更多），配合「主操作固定在面板底部」。
