# PureTerm

[中文版本](CHANGELOG_zh.md)

All notable changes to PureTerm are documented here. This file follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and uses [Semantic Versioning](https://semver.org/).

The `[Unreleased]` section is for changes that have landed but are not in a release yet. Before creating a version tag, move those entries into a dated version section. The release workflow refuses a tag unless the matching version section exists.

## [Unreleased]

### Added

- Give the terminal page its own right-hand tool rail. **Files** and **Monitor** become two 34px buttons in a 52px column of the terminal workspace, sharing one collapsible panel and one grip. Clicking the active tool collapses the panel and clicking the other replaces its content, so at most one panel is open and a new tab starts with none. Each terminal tab remembers which tool it had open and how far its split was dragged; no tab inherits another's. The rail is a column of `#session-workspace` rather than of the shell, so it leaves with the terminal page instead of staying behind on Hosts or Keychain, a connecting, failed or disconnected tab keeps it visible with both buttons disabled and the panel closed, and the failure view is confined to the terminal column rather than covering it. Closing the panel returns focus to that tool's button. Above 820px the panel takes width from the terminal; at or below 820px it stacks under it behind a horizontal grip, and the rail stays on the right in both. The rail is excluded from the split ratio, which describes only the terminal and panel tracks.
- Guard quitting when SSH work is active or its state is unknown. Closing the last window on Windows/Linux, the menu Quit, and Cmd+Q now share one decision point: the shell reads the Host's accepted-work counts, asks before destroying the window when there is activity or the counts could not be read, closes admission with a shutdown lease, drains finite accepted work, and rechecks inside the lease before stopping the Host. Cancelling, a conflicting request, or a failed preparation leaves the window, its WebSocket, and every session running, and restores admission.
- Keep one Desktop profile per SSH data directory. A launch takes a single-instance lock and binds the directory to one profile in `desktop-profile.json` before it reads a launch profile or opens a Host; the record is created once with exclusive create and is never auto-rewritten or auto-rebound. A second launch on the same directory focuses the owner, a launch on a different directory is told so rather than being switched, and a launch whose Chromium `userData` does not match the record stops with an explicit message instead of letting two processes write one store. Moving existing data to another profile needs a deliberate data/encryption migration; PureTerm will not rebind it for you.
- Add bounded Host-failure diagnostics and an explicit recovery choice. An unexpected Host exit, a failed startup handshake, or a shutdown timeout writes one allowlisted report under `<userData>/diagnostics/host/` — version, time, platform, architecture, phase, reason, and process facts only, written 0600 through a temporary file and rename, newest five retained — and then offers a native choice of restarting the application or quitting. A restart relaunches with the same data directory and switches but does not restore SSH sessions or terminal tabs.
- Give workspace shortcuts one owner. Desktop and the standalone/attached browser resolve the same neutral binding table, so a key is consumed at most once; the native path stays inert until the renderer reports a context, and the help list is rendered from the same bindings the matcher uses. Ctrl/Cmd+W closes the active tab, Ctrl+Tab / Ctrl+Shift+Tab cycle tabs on every platform, Ctrl/Cmd+E opens Files, Ctrl/Cmd+` focuses the terminal, Ctrl/Cmd+K focuses host search, and Escape dismisses the host editor.

### Changed

- Install an update only after the Host acknowledges a clean, signal-free exit. Update preparation now uses the same shutdown coordinator as an ordinary quit, with a stricter completion rule: a forced termination never counts as a successful install, and a cancelled or busy preparation keeps the downloaded update and the running Host instead of treating a failed preparation as a failed install.
- Make the Host's lifecycle observable and its shutdown honest. The Host and Web Host expose accepted-work counts and an admission lease — `inspectActivity`, `prepareShutdown`, `drainAccepted`, `cancelShutdown` — through the public API and the private parent/child RPC, and `stop()` returns a `HostStopResult` whose `graceful` is true only after a shutdown acknowledgement and a clean exit with code `0` and no signal. A version-1 private-RPC reply can now carry a structured `wireError` in place of a bare string.
- Remove the terminal page's session toolbar. The 40px band repeated what the rest of the screen already said — the session state and `user@host:port` are the status bar's own cells, the address is also the tab's tooltip and the failure page's endpoint, and the raw log line is the last entry of the failure page's log list — so the terminal page now draws the same two fixed bands as the library pages and the terminal keeps the 40px. A dropped connection gets a **Reconnect** banner as the first row of the terminal cell, above the terminal rather than over it, so the scrollback stays readable; it costs no height while the session is up. The failure verdict returns to the failure page as a chip beside the host name it was read from, and the raw line it was read from is dropped rather than moved. **Disconnect** goes with the band: closing the tab (or Ctrl/Cmd+W) is now the only way to end a session, which is what the status bar hint already said, and `ClientTerminal.disconnect()` had no other caller. This is a behaviour change — a tab's scrollback is no longer kept on demand.

### Fixed

- Make a Host-failure restart hand the profile over instead of racing for it. The replacement is now spawned with the predecessor's process id and waits for that process to exit before claiming single-instance ownership, and the predecessor exits only once the replacement is confirmed alive. Previously the replacement could start while the predecessor still held the lock, be treated as an ordinary second instance, and quit silently — no window, no report, nothing on screen — which is what happened on Linux.
- Stop the status bar from widening the shell. `#app`'s single column was implicit `auto`, so the status bar's no-wrap fields — 925px of min-content at an 821px viewport — widened the whole shell and pushed the terminal tool rail past the right edge of the window. The column is now `minmax(0, 1fr)`, so content that does not fit is clipped inside its own cell instead of moving the shell.
- Stop a shortcut from being consumed twice, and stop workspace shortcuts from stealing IME or AltGr input. Both entry points resolve one binding table, extra modifiers never match, key-up is ignored, a held key does not repeat a destructive close, and an IME composition or an open dialog owns the keyboard. The shortcut help no longer claims that macOS replaces Ctrl with ⌘ for Ctrl+Tab, which uses a literal Ctrl on every platform.
- Do not read an unreadable activity count as zero. A failed inspection is reported to the user as unknown rather than as no work, so a quit cannot silently skip the confirmation.

### Security

- Keep Host-failure reports free of secrets. Each report is rebuilt from an allowlist, so host names, paths, credentials, tokens, commands, and terminal output never reach `diagnostics/host/`.

## [0.1.0-alpha.2] - 2026-09-30

### Added

- Add `@pureterm/i18n`, one message catalog and one `t()` shared by the browser UI and the Electron shell, with English as the source of truth and a complete Chinese translation. The two catalogs are held key-identical, placeholder-identical and free of untranslated error codes by test, so a missing translation fails the build rather than rendering a blank. `@pureterm/protocol` gains `HOST_ERROR_CODES`, `WireError` and `HostError`, so a failure can cross the wire as an identity plus its parameters instead of a pre-rendered sentence; the Host emits codes and never imports the catalog. This change lays the foundation only — the producers and the interface are moved onto it separately.
- Add a functional Keychain library with import/paste/drop, private-key and passphrase validation, derived public keys/fingerprints, search, card/list views, safe editing and deletion protection. Hosts select saved keys and authenticate in independent terminal tabs. Desktop uses an atomic system-encrypted vault; Web keys and associations are isolated per client and never persisted.
- Add session resource monitoring. Each session gains a resource drawer in the same right-hand slot as the remote file table — the **Resources** control sits left of **Files** and opening one drawer closes the other — closed by default and reporting the remote host's CPU, memory, load, root-filesystem disk usage, network throughput and uptime from a Linux probe every five seconds. The drawer stacks the metrics as sections, with occupancy bars for CPU, memory and the root filesystem, a receive/transmit sparkline for network, and the network rate in kB/s (carrying into MB/s past 1024 kB/s). Collection runs only while the tab is selected, connected, visible, with the drawer open and not paused, and stops on close, pause, hidden page, tab switch, disconnect or unload, so a closed session costs the remote nothing. A metric the remote does not supply stays empty with its reason instead of reading as zero, a remote that is not Linux reports that monitoring is unsupported, and CPU and network read as warming up until a second probe supplies a baseline. The status bar also fills its cipher and host-key cells, from the SSH handshake rather than from this drawer.

### Changed

- **0.x integration break:** replace Desktop’s `window.sshAPI` and SSH business IPC with `window.puretermDesktop` for minimal bootstrap/readiness and the shared child-owned loopback Web Host for SSH/SFTP, hosts, and Keychain. The Electron window loads from `pureterm-app://app/`; existing SSH data and user-facing operations remain available. Standalone Web stays independent, and `SSH_CORDIS_NO_WEB_CARRIER=1` limits only attached browser access.
- Replace the native title bar with a compact PureTerm top bar and auto-hide the Windows/Linux menu bar while retaining its keyboard shortcuts.
- Consolidate host creation behind the New Host action; remove duplicate top-bar, navigation, search, Terminal, and Ctrl/Cmd+T launchers.
- Make host-card gestures explicit: single-click selects, Edit opens the host drawer, and double-click opens a new terminal tab.
- Open every SSH connection in its own persistent terminal tab beside Hosts, with isolated output, independent disconnect/close/retry, and session-scoped SFTP state. Handle concurrent handshakes, late results from closed tabs, and closure of every session on WebSocket loss.
- Add editable host labels, working card/list switching and shortcut help; remove unimplemented placeholder actions. Keep the file panel below the terminal without covering its prompt.
- Rework the shared PureTerm workspace around a mature dark Hosts dashboard, Termius-inspired navigation rail and toolbar, searchable host cards, and a focused connection workspace while preserving responsive host/SFTP surfaces and keyboard focus states.
- Make maintained Markdown documentation English-first while retaining complete Chinese translations.
- Add English-first development guides with paired Chinese translations.
- Add `VERSION.txt` as the source baseline and generate UI version and changelog metadata.
- Render the interface in Inter, bundled locally so the page makes no remote font request, and resolve monospace text through one shared stack instead of the several hand-copied ones it used to carry. Text weights are limited to 400/500/600/700: the off-scale 650/750/800 values could not be rendered by the Chinese and system fallback faces, which answered with a synthetic bold on 13px text.
- Move the terminal to a neutral ANSI palette on a darker canvas. Black-on-terminal text is no longer exactly the background colour, and the dimmed prompt colour now clears 3:1 against the canvas.
- Resolve every interface colour through a token. The system lives in `packages/ui/src/styles/tokens.css`, which carries a dark and a light group, and no other file in the stylesheet may name a colour. Text, accent and status colours are measured against the surfaces they paint on and held to WCAG AA, including status labels on their own tint; the translucent fill, border and scrim steps carry the triplet of the colour they tint, asserted per theme.
- Render the interface in the neutral graphite palette. The pre-redesign blue-purple surfaces, the `#a7c4ff` accent and the translucent hairlines are gone, along with the guarded register that held them: six graphite steps carry depth, one accent carries state, and separation comes from hairlines instead of from shadows. The light group is complete and under test, but still unreachable — the control that writes it ships with the chrome rebuild.
- Hosts and Keychain are now tables with a header row: name, address, user, authentication and last-saved date for hosts; name, type, fingerprint, associated hosts and creation date for keys. Card view is one click away and no longer the default. The authentication column says whether a key came from the keychain or a local file, which is the fact that decides whether a host is usable.
- The connection editor docks into the window instead of covering the host list, at the same 322px as the key editor, and the two now share one width token.
- Breakpoints across the workspace screens collapse from six to three (1100 / 820 / 620). Below 820 the hosts table drops the user and authentication columns rather than squeezing them.
- Sync the colours that live outside the stylesheet with the ramp they must match. The Electron window background and the page's `theme-color` were two hand-copied values of one retired colour; they now follow `--c-chrome` and a test fails when they drift.
- Rebuild the application chrome: the navigation sidebar becomes a 52px icon rail, the top bar drops from 76px to 40px and now carries the brand mark, the session tabs and two new switches, and a 24px status bar reports connection state, endpoint, terminal size and version.
- Add a theme switch and a row-density switch. The light theme is now reachable in the running app, and both choices are remembered. Because the page's Content-Security-Policy forbids an inline pre-paint script, a stored light theme applies one frame after start.
- Give the session its workspace: the terminal and the remote file table are two columns with a draggable grip that is a real separator (focusable, arrow-key steppable, clamped so no pane can be dragged away), and each session keeps its own ratio. Below 820px the file table stacks under the terminal instead of overflowing the window.
- Lay the remote directory out as a four-column table — name, size, mode, modified — sharing one column template with its header. Mode is drawn from the permission bits the stack has always returned and the screen never showed, and a server that sends no attributes reads as an em-dash rather than as `000`. A breadcrumb of clickable hops sits above it, and the path field stays, because typing `/var/log` should not require clicking down a dozen directories.
- Say which step a failed connection stopped at: four nodes with the one that died marked, the stages before it marked as passed, and the link broken where it gave out. Unclassifiable failures collapse the route rather than drawing dots that claim nothing, and the stage is repeated in words because the graphic is hidden from assistive technology.
- Toast completed events — saved, deleted, a background session that connected — in the bottom-right corner with dismiss-on-click, a three-deep stack and correct live-region roles; standing instructions and field-validation prompts deliberately stayed inline.
- Give the host list a skeleton at the height its rows will occupy, an explicit "this could not be read" block distinct from a capability being switched off on this carrier, and a retry.
- Align the workspace with the design prototype's control scale and arrangement. The 38px floor becomes 28px across buttons, inputs, selects and the 40px toolbars they sit in, and the corner ladder collapses onto `--r-1` for controls, `--r-2` for rows and `--r-3` for dialogs, leaving the 12px `--r-4` with no consumer. The hosts and keychain headers each become a single 40px row, the connection editor re-cuts its sections, switch and footer, the session toolbar carries the failure verdict so the failure page stops repeating it, the top bar's brand reads as one line — `PureTerm / Vault`, naming the area the screen is showing — instead of a stacked title, the empty state separates from the file table's inline placeholder, and the shortcuts dialog gains a title bar and a footer.
- Finish the top bar against the prototype. The library tab leaves the title bar: the brand's `/ Vault` already names the screen and the rail's Hosts item is what switches library pages, so the tab said one thing twice — and it was also the only active tab in the bar whose `--line` hairline a later, equal-specificity rule cancelled, so the prototype's `.tab.on` outline was missing from it and is missing from nothing now that it is gone. The brand suffix takes the prototype's `--tx-4` rung (2.79:1 on the chrome ground in dark, 2.28:1 in light) under a named, audited exemption in `stylesheet-contract.test.mjs`, because a decorative restatement of what the rail and the panel heading already say is the one text position that can carry it.
- Make the top bar's window buttons desktop-only. The minimize/maximize/close cluster leaves `packages/ui/src/index.html` and the shared stylesheet, and a second manifest — `packages/ui/src/desktop.css`, built as its own esbuild entry — carries the four rules; `services/chrome.ts` links that sheet and builds the three buttons at runtime, only when the desktop bridge offers `windowControls`. The standalone Web entry now carries neither the markup nor the rules, which is what its built `app.css` shows: no rule in it mentions `.window-control`. macOS draws nothing and keeps its own traffic lights — `drawsOwnWindowControls` in the desktop platform plan is the one place that answers which platforms draw their own, so Windows and Linux keep the cluster they had while macOS, which had no native caption buttons reserved for it once the title-bar overlay was removed, is not given a second set beside its traffic lights.
- Make SSH exec bounded and cancellable, and add the monitoring protocol. `exec` accepts an abort signal and a deadline that includes channel acquisition, bounds retained stdout plus stderr at 65,536 bytes, and rejects an overflow rather than returning a partial result; the `ExecResult.truncated` flag is retired. The protocol gains the additive `monitor:start`, `monitor:stop` and `monitor:update` pair, the request-side-free `session:facts` event, and the validation rules that go with them. Existing terminal, SFTP and host operations are unchanged.
- Follow the theme in the terminal. The light group gains its own canvas, foreground, cursor and selection plus its own sixteen-entry ANSI palette, so a light session is no longer a dark hole in a white shell; the dark group keeps its values and its ties. `terminal-view.ts` picks the palette from `data-theme` and re-reads every token on demand, and `ClientChrome` broadcasts the change — once at start-up, once per switch — so the idle pane and every open tab are re-coloured instead of each terminal staying on the group it was built in. The pane background follows with no rule change, because `terminal.css` already paints `--term-bg`.
- Fit the library card grids to the panel. Card view used three fixed columns on both library screens, so a lone card took a third of the width and left the rest empty; each grid now takes an `auto-fill` track with a 200px floor for hosts and 220px for keys, and the media and container queries that only restated the column count are gone with it.
- Put the library cards' data line on the name's own left edge. Both card views kept the table's data cell — the host address, the key fingerprint — and a cell is a row of the card's own grid, so it could only ever sit under the avatar: 72px left of the name it belongs to on the hosts card, and flush against the card's left edge on the key card, whose cell had no table padding to hold it in. Each is a line of the name column now, so the avatar, the name and the value form one block. The host address reads as the connection string, `user@host:port`, because a card has no user column to say the user anywhere else.
- Put the whole browser interface on the message catalog and add a language switch. Every string the page can render — the hosts table and its cards, the connection editor, the Keychain library, the session tabs, the failure page and the log it copies, the remote file table with its breadcrumb and hints, the resource drawer, the status bar, the toasts, the confirmations and the accessible names — now resolves through `t()` in the active language, and a third switch beside the theme and density toggles moves the screen between English and Chinese, writes `<html lang>` and is remembered in the same preference record as the other two. Sentences the client composes in JavaScript and then holds on to — a terminal tab's failure verdict and its log, a file row's hint, the drawer's last message, a standing notice — are stored as a key plus its parameters rather than as finished text, so a switch re-renders them instead of leaving the previous language on screen; every plugin that composes text listens for the change. `index.html` ships English and carries `data-i18n`, `data-i18n-attr` and `data-i18n-html` for the static text, because the page's Content-Security-Policy forbids the inline pre-paint script that would otherwise spare a non-English reader one English frame. The two `toLocaleDateString()` calls that printed dates in whatever locale the browser was in now use the same `YYYY-MM-DD HH:mm` as the rest of the interface, so a date does not change language with the switch, and every unit format is left as it was. Developer invariants — a missing DOM id, a second client mounted on one document — stay English and stay out of the catalog, because they are build and configuration errors rather than text for a reader.
- **0.x wire break:** a failure now crosses the wire as `{code, params, message}` instead of a pre-rendered Chinese sentence. The Host raises `HostError` codes in every layer that can fail — SSH, SFTP, the Keychain, the Host facade, the terminal bridge, the session store and the resource monitor — the carrier turns them into `WireError`, and `monitor:update` carries `error` in place of `message`. The interface turns a code back into a sentence from the catalog, one per declared code, and a compile-time assertion refuses a code with no sentence in either language; a code the client does not recognise falls back to the diagnostic message rather than rendering nothing. The failure page, the terminal tab, the file-row hint, the Keychain notice and the resource drawer therefore follow the language switch, and `packages/ui/src/failure-diagnostics.ts` stops matching the Host's Chinese sentences with fourteen regular expressions and reads a code table instead. A client that loses the socket supplies `transport.disconnected` itself, because no backend is left to say why the session ended. Developer log lines move to English and out of the catalog.
- Put the Electron shell's own text on the same catalog, and give the page a way to say which language it is showing. The application menu, the native private-key picker's title, the "Host stopped" box and every update dialog were the last surfaces that were Chinese or English by accident — they sit outside the document, where no switch could reach them. The renderer owns the preference, because it has the switch and the stored record and the main process can read neither, so it reports rather than being asked: `DesktopBridge` gains `reportLocale`, the main process narrows the value with `isLocale` before believing it and rebuilds the menu on the spot, and until the first report the menu is English, which is the catalog's source language. `PickedPrivateKey.error` becomes a `WireError` for the reason a failure crosses the wire as one: the file dialog belongs to the main process, but the sentence belongs to whoever knows the language. Desktop runtime log lines move to English with the rest.
- Move the standalone Web CLI's own text to English, out of the catalog. `--help`, the argument errors and the `[pureterm:web]` lines were the last Chinese the application prints outside the catalog, and the CLI has no switch to reach them with: it prints once and exits, before any page exists to carry a preference, and it has no reader it could ask. English is the catalog's source language and the page's default, so the terminal and the page it tells you to open now speak the same language; the text stays out of the catalog because a catalog exists to be switched, and nothing here can be. The duplicate port-range error in `apps/web/src/server.ts` follows it.
- Bring the maintained documentation back in step with the code after the message catalog landed. `@pureterm/i18n` was missing from every package listing — `AGENTS.md`, `README.md`, `LAYOUT-PROPOSAL.md`, the development guide and the Desktop README — and from the boundary rules that say what may import what; `window.puretermDesktop` was still described as accepting only the readiness report, when it also accepts the language report the shell needs for its own menu and native dialogs; the design system still said the top bar carries two switches, when the language switch is the third; and the English documents named two session controls by their Chinese labels, which the English interface no longer shows. The development guide gains a section on user-facing text, so the catalog's rules — English is the source, a missing translation is a compile error, a failure crosses the wire as a code, and developer logs and the CLI stay English and out of the catalog — are written down where a contributor will find them.
- Pin Electron to 43 so the Desktop app runs on macOS 12. Electron 44 declares `LSMinimumSystemVersion = 13.0`, so on Monterey its binary stopped at `dyld` with `Symbol not found: (_OBJC_CLASS_$_SMAppService)` — a macOS 13 API — before a line of application code ran, which took `verify:electron` and every Electron-backed smoke suite down with it. Each major states its own floor and the boundary is clean: 38 and below need Big Sur, 39 through 43 need Monterey, 44 needs Ventura. The pin becomes `^43.7.5`; nothing in the repository required 44, no code uses an API that 43 lacks, and 43 is still inside Electron's supported window of the latest three majors. `npm run verify:electron` now completes — it never had on a Monterey host — across all seven flows, including the shared client-lifecycle suite and the standalone-browser run. The cost is one major behind: anything at or above 44 will require macOS 13, so a contributor still on macOS 12 stays on 43.
- Report whether credentials can actually be encrypted, instead of offering storage the machine cannot protect. `safeStorage` falls back to a plaintext backend wherever no system keyring exists — the headless Linux CI runner, and any desktop without one — yet the Desktop entry point told the Host `credentialPersistence: 'encrypted'` regardless. The Host therefore believed it could seal a key, `seal()` returned nothing, and the Host correctly refused the write. The capability is measured now rather than assumed: `CredentialProvider` carries a `credentialPersistence` of `'encrypted'` or `'session'` — distinct from `persistent`, which says whether storage survives a restart, not whether it can be encrypted at all — the parent reports it over `platform:capabilities`, and the Host child validates and forwards it. Where it reads `'session'` the **remember credentials** switch is off and its hint says the credential lasts only for this page, rather than offering a save the Host would reject. Both smoke paths assert the outcome their capability promises, sealed and authenticated or refused with nothing reaching disk, so the Linux Electron job completes instead of failing on the refusal.
### Fixed

- Hide the column header in card view on both library screens. The six labels sat over a grid with a single track, so they named columns that were not there; the header now follows the `.card-view` class the view toggle writes, exactly as it already followed the empty element's `hidden` attribute.
- Stop a session from taking the shell apart. Connecting used to add a `session-mode` class that `chrome.css` answered by hiding the navigation rail and collapsing the body to a single track, so a connected screen read as a frame that had been lost rather than narrowed. The rail now keeps its 52px track through a session and keeps switching library pages — which is what it already did, since Hosts and the brand were always the way back — and the class and its two toggles are gone with the rule, because nothing else read it. The prototype's shell is rail + main (+ inspector) on every screen it draws.
- The status bar shows only fields the backend actually reports. The negotiated cipher and the server host-key algorithm are now filled from the SSH handshake, so they are no longer among the absent cells. The session’s own uptime and the transfer rate remain absent rather than approximated: the snapshot carries the **host’s** uptime, which is a different figure and must not be printed as the session’s, and no transfer-rate channel exists.
- Two `@media (max-width: 620px)` blocks in the hosts stylesheet were silently overriding each other's scroll model; there is now one.
- The view toggles on both library screens described the view you were leaving rather than the one you got, and the keychain policy line — the sentence that states private material never reaches disk in plaintext — was small text under a heading. It is a banner now.
- Delete the chrome styles that named nothing: the navigation toggle and its collapsed state, the window-control rules with no matching markup, the update pill, and a shell state class that no code ever added.

### Security

- Give the Desktop window a separate main-process bearer token for its exact WebSocket request; keep it out of page URLs, DOM, browser cookies, and storage.

## [0.1.0-alpha.1] - 2026-09-16

### Added

- Electron Desktop with an independent Node Host process for SSH, SFTP, storage and Cordis services.
- Shared Cordis Client lifecycle across Desktop IPC and the local Web entry, including scoped cleanup and browser cache restoration.
- Windows NSIS packaging, macOS DMG/ZIP and Linux AppImage CI artifacts.
- GitHub Releases update checks with user-confirmed restart installation.
- Local-only Web access with session-only browser credentials and no user or tenant isolation.

### Security

- Desktop credentials remain protected by the operating system credential store; the Host process accesses them through a private IPC capability.
- Release builds exclude optional native SSH accelerators and do not contain GitHub credentials.
